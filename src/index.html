Tests <rtsp-over-websocket>'s src attribute: paste a full RTSP URL and Set src assigns it directly (playerEl.src = ...) instead of setting hostname/username/password/channel/profile/device/etc. one by one — the element parses the URL into all of those itself (RTSPOverWebSocket.ts's applySrcAttribute()) and connects automatically. Setting it again while already connected reconnects with the new URL.

URL parameters — each of these can be given as a real ?query=value, or (legacy) as a /key=value path segment anywhere after the channel, e.g. .../recording/play.smp/device=camera/gmt=9/start=.../end=.../overlappedid=0. An explicit value from either source always wins over anything applySrcAttribute() would otherwise infer from the URL's shape.
  • device — camera or nvr; resolved from this, then the element's existing attribute, then defaults to camera.
  • mode — live (default) or playback. If omitted entirely, a literal recording path segment (e.g. .../0/recording/play.smp) still infers playback on its own; an explicit mode= always overrides that inference.
  • gmt — the device's UTC offset in hours (e.g. 9 for KST). Needed to correctly convert a compact or naive start/end value to true UTC — apply it before start/end in a path-embedded URL (parsed left to right) so the conversion sees the right offset.
  • start / start_time / start-time / starttime — playback range start; all four spellings are equivalent. Accepts a compact YYYYMMDDHHMMSS digit string, or a full ISO string (naive — 2026-09-03T14:07:24, interpreted in the gmt zone — or with an explicit Z/±HH:MM designator, trusted as an absolute instant).
  • end / end_time / end-time / endtime — playback range end, same accepted shapes as start.
  • overlappedid / overlap / overlapped-id — disambiguates overlapping recordings covering the same time range on the device.
  • session / sessionkey — resumes an existing RTSP-over-WebSocket session key instead of starting a new one.
  • statistics — boolean flag (present/=true is on, absent/=false is off; a bare ?statistics counts as present). Shows the on-screen fps/bitrate/latency statistics overlay panel this element renders over the video.
  • controls — same boolean-flag convention as statistics. Shows the native <video> element's own playback controls (play/pause, seek bar, volume) when rendering through the video tag mode; has no visible effect in canvas tag mode, which has no native controls to show.
Only real ?query params are joined with &; a path-embedded mode= (or any other pair) after another path-embedded pair must still be its own /key=value segment, not appended with & or / onto the previous one's value.
